# 09. Svelte UI 구조

## 위치 / 빌드

```
ui/
├── package.json           — name: "agent-ui"
├── svelte.config.js       — adapter-static + fallback='index.html'
├── vite.config.ts         — proxy 50051
├── tsconfig.json
├── components.json        — shadcn-svelte config
├── static/                — favicon 등
├── src/
│   ├── app.html
│   ├── app.css            — Tailwind base, daisyui, theme tokens
│   ├── lib/
│   │   ├── api/           — REST/SSE 클라이언트
│   │   ├── components/    — UI 컴포넌트 (shadcn primitives 등)
│   │   ├── stores/        — 전역 상태 (auth stub 포함)
│   │   ├── styles/
│   │   ├── utils/
│   │   └── ...
│   └── routes/
│       ├── +layout.svelte — 단순 헤더 (Trace 메뉴 제거됨)
│       ├── +layout.ts     — ssr=false, prerender=true
│       ├── +page.svelte   — / → /agent 리다이렉트
│       └── agent/         — portal 의 agent 메인 페이지 + 32 컴포넌트
└── build/                 — vite build 산출물 (//go:embed 대상)
    ├── index.html
    ├── _app/immutable/    — JS/CSS chunks
    └── favicon.svg
```

빌드:
```bash
./build-ui.sh              # npm ci (필요 시) + npm run build
# 또는 직접
cd ui && npm run build
```

산출물 크기:
- `_layout.svelte` 약 33KB (헤더만이라 작음)
- `agent/_page.svelte` 약 545KB (메인 페이지 + 32 컴포넌트 + scenario-canvas + iotest)
- 공통 chunks (deck.gl, jmuxer, echarts, bits-ui 등) ~2MB
- CSS ~130KB
- **합계: 약 2.5MB** (gzip 약 800KB)

## portal/frontend 와의 차이

처음 부트스트랩 시 portal/frontend 의 src 전체를 통째로 복사한 후 다음만 변경:

### 1. 제거된 라우트 (9개)

portal 의 `routes/` 중 agent UI 가 아닌 것:
- `admin/` — 시스템 관리 (사용자/권한 관리)
- `bitbucket/` — git 통합
- `dashboard/` — 전사 대시보드
- `devtools/` — 개발 도구 (bin-mapper, perf-generator)
- `log-search/` — 로그 검색
- `remote/` — VM Guacamole 원격 데스크탑
- `storage/` — MinIO 파일 브라우저
- `testdb/` — 테스트 케이스 DB CRUD
- `ufsinfo/` — UFS 펌웨어 정보

### 2. `routes/trace/` 완전 제거

portal 의 `/trace` 페이지는 **MinIO archive 의 풀 화면 시각화**라 standalone 에선 무의미. trace 결과는 `/agent` 안의 `AgentTraceResultSheet` 모달로 즉시 확인.

### 3. `routes/+page.svelte` 교체

원래 portal 의 `+page.svelte` 는 OAuth 로그인 페이지. standalone 에선 `/` → `/agent` 자동 리다이렉트.

```svelte
<script lang="ts">
  import { goto } from '$app/navigation';
  import { onMount } from 'svelte';
  onMount(() => goto('/agent', { replaceState: true }));
</script>
<div class="flex h-full items-center justify-center text-sm text-muted-foreground">Loading…</div>
```

### 4. `routes/+layout.svelte` 교체

원래 portal `+layout.svelte` 는 **498줄짜리** 사이드바 + 메뉴 + 알림 + 권한 체크 등 풀 portal 셸. standalone 에선 간단한 헤더 한 줄:

```svelte
<header class="border-b px-4 py-2 flex items-center">
  <h1 class="text-sm font-semibold tracking-tight">Agent Standalone</h1>
</header>
```

### 5. `lib/stores/auth.svelte.ts` stub 화

portal 은 `/api/auth/me` 호출 + OAuth 리다이렉트 등 복잡한 인증 흐름. standalone 은 **항상 ADMIN 인증된 상태로 응답**하는 stub. API 시그니처는 portal 과 100% 동일하게 유지 (다른 컴포넌트가 `auth.hasPermission()`, `auth.isAdmin` 등을 호출하므로).

```ts
let state = $state<AuthState>({
  authenticated: true, role: 'ADMIN', name: 'standalone', ...
});
export const auth = {
  ...,
  hasPermission: (_) => true,
  hasMenu: (_) => true,
  // ...
};
```

### 6. `lib/api/client.ts` 의 404 처리 추가

portal 은 비-200 응답을 throw 했지만, standalone 에서는 **만료된 잡 status/result 가 404 + state body** 형태로 자주 옴. 정상 데이터로 받기 위해 client.ts 에 분기:

```ts
if (res.status === 404) {
  const body = await res.text().catch(() => '');
  try {
    const parsed = JSON.parse(body);
    if (parsed && parsed.state) return parsed as T;
  } catch { /* ignore */ }
  throw new Error('Not found');
}
```

### 7. `vite.config.ts` proxy target 변경

portal: `http://localhost:8080` (Spring Boot)
standalone: `http://127.0.0.1:50051` (Go agent) + WebSocket 도 같은 포트

### 8. `package.json` name 변경

`frontend` → `agent-ui`

## 핵심 컴포넌트 인벤토리

### `routes/agent/`

#### 메인 페이지 (`+page.svelte`)
3 패널 레이아웃:
- 좌측: `AgentContextPanel` (서버 선택, 디바이스 목록, 연결 상태)
- 중앙: 7 모드 탭 (선택된 모드에 따라 컴포넌트 교체)
- 우상단: `AgentFloatingJobCard` (떠있는 진행 잡 카드)

전역 state: `servers`, `selectedServerId`, `devices`, `selectedDeviceIds`, `activeJobs`, `jobHistory`.
페이지 로드 시 running 잡 자동 복구 (`getJobStatus` 호출 후 SSE 재구독).

#### 모드별 컴포넌트

| 모드 | 컴포넌트 | 핵심 동작 |
|---|---|---|
| benchmark | `AgentBenchmarkForm` | Tool/params 편집, preset CRUD |
| scenario | `AgentScenarioBuilder` + `scenario-canvas/*` | 시각적 DAG 빌더 |
| trace | `AgentTraceForm` | 단일 디바이스 ftrace start/stop |
| iotest | `iotest/IOTestForm` + `IOTestEditor` + `IOTestProgressView` | thread 편집 + 진행 timeline |
| macro | `AgentMacroRecorder` | 5단계 위저드 (앱 선택→녹화→편집→저장) |
| schedule | `AgentScheduleView` | cron CRUD |
| results | `AgentResultsView` + `AgentResultDetailSheet` | DB executions 표 + 잡 상세 |

#### Sheet (drawer) 컴포넌트

- `AgentScreenSheet` — scrcpy 스트리밍 (WebSocket H.264 + JMuxer 디코드)
- `AgentMonitoringSheet` — 실시간 CPU/MEM/Disk 그래프 (120-point sliding window)
- `AgentServerSheet` — 서버 등록/편집
- `AgentResultDetailSheet` — 잡 결과 상세
- `AgentTraceResultSheet` — trace 통계 차트 + raw events scatter
- `AgentMacroResultView` — macro replay 후 OCR 결과 + 스크린샷

#### Scenario canvas (`scenario-canvas/`)

`@xyflow/svelte` 기반 시각적 DAG 빌더 (5 파일):
- `ScenarioCanvas.svelte` — 메인 캔버스, drag-drop, connection draw
- `StepNode.svelte` — 사각 노드 (benchmark/shell/cleanup 등)
- `ConditionNode.svelte` — 다이아몬드 (분기)
- `LoopGroup.svelte` — 루프 영역 highlight (NodeResizer)
- `NodePalette.svelte` — drag source 카드들 (Loop / Condition / Benchmark / IOTest / Shell / Cleanup / Sleep / Trace Start / Trace Stop / App Macro)
- `CanvasToolbar.svelte` — zoom, reset, run
- `ExecutionMiniCanvas.svelte` — 실행 진행 상태 read-only 표시
- `serializer.ts` — DAG ↔ proto ScenarioStep[] 변환

### `lib/components/`

- `data-table/` — TanStack table-core 기반 virtual-scrolled paginated 테이블
- `ui/*` — shadcn-svelte primitives (button, dialog, sheet, tabs, select, popover, tooltip 등 40+)
- `perf-chart/PerfChart.svelte` — ECharts wrapper
- `DataTableShell.svelte`, `ConfirmDialog.svelte`, `MoveLogo.svelte` 등

### `lib/api/`

- `client.ts` — fetch wrapper + 404 with state body 처리
- `agent.ts` — typed REST 클라이언트 + SSE EventSource helpers (60+ 함수)
  - 모든 portal endpoint 1:1 매핑
  - `createJobProgressSource(serverId, jobId)`, `createMonitoringSource(...)` SSE 헬퍼
  - `getScreenWebSocketUrl(serverId, deviceId)` WS URL 생성
- `trace.ts` — trace 결과 helper
- `traceLogs.ts`, `traceExport.ts`, `agentTraceArchive.ts` — 옵션
- `logSearch.ts` — (portal 잔재, standalone 미사용)

### `lib/stores/`

- `auth.svelte.ts` — **stub** (위 설명)
- `entityChange.svelte.ts` — 다른 탭에서 entity 변경 시 broadcast
- `menu.svelte.ts`, `tentacle.svelte.ts`, `reparse.svelte.ts`, `session.svelte.ts`, `slotHoverStore.svelte.ts` — portal 잔재 (대부분 standalone 에선 미사용)

## 사이즈 프리셋 (resize-ui.sh)

portal 의 `resize-ui.sh` 가 그대로 복사되어 있음. 3단계:

```bash
./resize-ui.sh compact   # 가장 작음 (body text-xs = 12px)
./resize-ui.sh default   # 중간 (text-sm = 14px)
./resize-ui.sh large     # 큼 (text-base = 16px)
```

각각 다음을 일괄 변경:
- `app.css` body class (text-sm/base/lg)
- `+layout.svelte` 헤더/네비 padding/icon
- `DataTable.svelte`, `DataTableToolbar`, `DataTablePagination`, `DataTableColumnToggle` — 행 높이, 텍스트 크기
- `tabs-list`, `tabs-trigger` — 탭 크기
- `perf-content/*`, `LogBrowserDialog`, `bin-mapper/*`

현재 적용: `compact` (사용자 요청). 변경 후 `npm run build` + go build 필수.

## SPA fallback (Go 측)

`server/http.go::spaHandler`:
1. 정적 파일이 있으면 그대로 서빙 (`/_app/...`, `/favicon.svg`)
2. 없으면 `index.html` 본문 반환 (SvelteKit SPA 라우팅)

`//go:embed all:ui/build` 가 빈 디렉토리에 fail 하지 않도록 `ui/build/.gitkeep` 을 커밋.

## 개발 흐름

### Hot reload (vite dev)

```bash
# 터미널 1: agent 백엔드
./agent --standalone -config config/devices.toml

# 터미널 2: vite dev (5173 포트)
cd ui && npm run dev

# 브라우저: http://localhost:5173
```

vite proxy 가 `/api` 와 `/ws` 를 `127.0.0.1:50051` 로 전달.

### 임베드 빌드

```bash
# 컴포넌트 수정 후
cd ui && npm run build      # → ui/build/

# Go 재빌드 (UI 임베드 반영)
cd .. && go build -o agent .

# 재시작
pkill -f 'agent --standalone'
./agent --standalone -config config/devices.toml
```

## portal 변경 동기화

portal/frontend 에 새 기능이 추가되면 standalone 에 가져오는 절차:

1. 변경된 파일 식별 (`git log` portal 측)
2. agent UI 측 해당 파일에 복사
3. **인증/메뉴/permission 호출**이 새로 들어왔는지 확인 — stub 으로 우회 필요
4. **새 portal endpoint** 호출 시 → agent server REST 핸들러 추가
5. `npm run build` + `go build` + 회귀 테스트

CLAUDE.md 와 메모리 [[project-standalone-mode]] 에 변경사항 기록.
