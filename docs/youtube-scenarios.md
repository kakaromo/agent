# YouTube 시나리오의 광고 처리

`youtube` 단계는 재생 구간과 광고 관측 구간을 구분합니다.

추가 시나리오 전체 목록과 일괄 가져오기 파일: [YouTube 시나리오 모음](examples/youtube-suite/README.md).

- `action=watch`, `seconds=60`: 화면에서 광고 표시가 없고 YouTube 미디어 세션이 재생 상태인 연속 표본 사이의 시간을 누적합니다. `seconds=0`은 연속 본영상 표본을 확인하고 종료합니다.
- `ad_timeout=180`: 광고와 미확인 상태에 쓸 수 있는 누적 시간입니다. 취소할 수 있고 한도를 넘으면 실패합니다.
- `action=inspect`: 현재 화면의 광고 표시를 기록합니다. 광고 링크는 누르지 않습니다.
- `action=feed`, `count=10`, `direction=down`: 각 스크롤 직전에 광고 표시를 기록합니다. 한 번에 한 화면씩 이동하므로 기존 일괄 스크롤보다 느립니다.
- `action=quality`, `quality=360p|720p|1080p`: 일반 영상의 화질 메뉴를 선택한 뒤 설정 메뉴에서 적용값을 확인합니다. 지원하지 않는 해상도로 대체하지 않습니다.
- `action=select_video`, `title` 선택 사항: 한국어 검색 결과에서 광고와 Shorts를 제외한 일반 영상을 선택합니다. 제목 접두어를 지정할 수 있으며 최대 8개 화면을 확인합니다.
- `action=control`, `target=play|pause|fullscreen|inline|next|previous|minimize`: 재생·일시정지·화면 모드는 적용 상태를 확인합니다. next/previous/minimize는 컨트롤 입력 성공만 확인하며 영상 ID나 축소 창의 재생 상태까지 검증하지 않습니다. 일반 영상의 메뉴 조작 중에는 잠시 정지했다가 재생을 복원할 수 있습니다.
- `action=network_cycle`, `seconds=10`: Wi-Fi와 모바일 데이터 상태를 저장하고 0~120초 끊은 뒤 원래 켜져 있던 망을 다시 켭니다. 취소·실패해도 복원을 시도하며 복원 명령 실패를 오류로 반환합니다. 이후 watch 단계에서 재생 복구를 확인합니다. 유선망·VPN·SIM 전환은 제어하지 않으며 기기 연결이 끊기면 복원이 실패할 수 있습니다.
- `action=panel`, `target=comments|description|close_panel`: 댓글·설명 패널을 열거나 닫고 제목으로 상태를 확인합니다. 버튼이 접근성 트리에 없으면 영상 아래 영역의 OCR을 사용합니다. 댓글 작성·링크 열기는 수행하지 않습니다.

재생 광고는 명시적인 광고 표시와 건너뛰기 버튼으로 판정합니다. 추천 목록의 스폰서 카드만 보이는 경우에는 본영상 재생 광고로 분류하지 않습니다. Shorts의 스폰서 표시는 광고로 기록하고 다음 카드로 넘깁니다. 때문에 Shorts 광고가 있으면 스와이프 수는 원래 반복 횟수보다 많아질 수 있습니다.

Shorts는 재생 중에도 미디어 세션이 STOPPED로 남는 버전이 있습니다. 이 경우 광고 검사를 통과한 화면의 Shorts 컨트롤에 '동영상 일시중지' 동작이 표시되면 재생으로 관측합니다. 컨트롤을 읽지 못하면 미디어 상태 확인을 사용하며, 재생을 확인할 수 없으면 미확인으로 남깁니다.

## 결과와 한계

Behavior 구간에 본영상 재생 관측 / 광고 관측 / 재생 미확인을 기록합니다. 원시 결과에는 `YOUTUBE_SEGMENTS`와 관측 초 수, 건너뛰기 시도 횟수가 포함됩니다. 바깥의 시나리오 단계 구간은 전체 소요시간이며, 안쪽 관측 구간과 중복되므로 두 시간을 더하지 않습니다.

화면 조회 사이에는 기본 3초를 기다리며 ADB/UI dump 시간도 더해집니다. 짧은 광고와 버퍼링을 완전히 검출하는 방식은 아닙니다. YouTube의 접근성 표시나 미디어 세션이 잘못되면 판정도 틀릴 수 있습니다. 기록 시간은 디코딩된 프레임의 재생시간이 아니라 관측 시간이며, 목표 시간보다 마지막 표본 간격만큼 길어질 수 있습니다. 화면 조회 자체가 기기 I/O와 DRAM 측정에 부하를 추가하므로 광고 처리가 없는 이전 결과와 직접 비교할 때 주의합니다.

## 화질 메뉴 OCR

재생 중 화면이 계속 움직여 UI dump가 실패하면 화면 OCR로 광고 표시를 찾고, YouTube 전면 앱과 미디어 세션의 PLAYING 상태를 함께 확인합니다. OCR도 실패하거나 전면 앱/재생 상태를 확인하지 못하면 미확인 구간으로 남깁니다. OCR에서 광고 문구를 놓치면 광고를 본영상으로 잘못 분류할 수 있습니다. `ocr_samples`는 이 보조 판정 횟수입니다.

일부 YouTube 버전은 화질 메뉴의 글자를 접근성 트리에 제공하지 않습니다. 이때 PC의 Tesseract와 `eng`, `kor` 모델을 사용합니다. Windows 기본 설치 경로 `C:\Program Files\Tesseract-OCR\tesseract.exe` 또는 PATH에서 찾습니다. 스크린샷의 메뉴 영역만 인식하며 임시 파일은 삭제합니다. 선택 후 설정 메뉴에서 요청 화질을 다시 확인합니다. 이는 실제 디코더 출력 해상도를 검증하는 것은 아닙니다.

자동 단위 테스트: `go test ./benchmark ./scenario ./macro`

실기기 검증: 일반 영상을 열고 `YOUTUBE_TEST_DEVICE`에 ADB serial을 지정한 뒤 `go test ./benchmark -run '^TestYoutubeDeviceQuality$' -v -count=1`. 이 테스트는 실제 기기의 화질을 변경하고 광고가 나오면 건너뜁니다. 환경 변수가 없으면 실행하지 않습니다.
